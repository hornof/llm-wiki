## Summary

Two [[greg-isenberg|Greg Isenberg]] X posts, 2026-09-10 and 2026-09-12, that form one argument. The first reads OpenAI's **Agents API** launch as *"the AWS moment for agents"* — the agent platform layer becomes rentable, so value moves up to whoever knows a specific job. The second is a 13-item list of *"the only businesses left to build,"* in which **domain-specific harnesses** and **vertical agents** both appear as separate line items. Together they are the investor/operator-side statement of the same shape [[goodhartproof-yc-demo-day-domain-specific-harness-2026-09-11|jessy observed at YC Demo Day]] the following day.

## Key Claims / Takeaways

### "The AWS moment for agents" (2026-09-10)

- **The claim**: *"OpenAI just shipped the Agents API, and everything that made agents hard to build is now something you rent instead of build. Keeping one running for days, remembering what it's doing, using tools, recovering when a step fails. Now it's an API call."*
- **The analogy**: before AWS you bought and ran servers, so only well-funded teams shipped scalable products; AWS made the hard part rentable and *"all the value moved up to whoever had the best idea for what to build on top."*
- **Who it hurts, stated plainly**: *"If your whole company is an agent platform, the thing you spent the last year building is now included for the price of tokens."* — first-party framing of the platform-layer squeeze.
- **Who it helps**: vertical builders. *"If the hardest engineering just became a line item, then the only thing left that's actually hard is knowing the job. Like what counts as a done claim, what makes a filing get rejected, where the money leaks."*
- **The wedge, concretely**: *"owning one painful workflow with your own tools, data, approvals, and a clear ROI."* Named domains: freight exceptions, insurance reviews, security triage, revenue leakage, healthcare admin, compliance ops.
- **The inference from OpenAI's own behavior**: against the "software is over, you'll just use Claude or ChatGPT" position — *"if that were true, OpenAI wouldn't be shipping infrastructure for other people to build agents on. They're telling you exactly what they think: the general model is theirs, the 10,000+ specific jobs it needs to be pointed at are yours."*
- **What the API actually is** (quoted OpenAI Devs post): *"Build and run cloud agents with the Codex harness, fully managed by OpenAI. We handle orchestration, long-running sessions, and context management."* Public beta. **The vendor ships its own harness as the managed substrate** — relevant to whether "harness" is a durable product category or an absorbed platform feature.
- **Closing frame**: *"It's becoming an agent internet, and every layer of it — the tools, the workflows, the boring jobs — gets rebuilt for a user that doesn't have eyes or hands."*

### "The only businesses left to build" (2026-09-12)

13 categories, verbatim: (1) AI-native service firms, (2) offline businesses, (3) distribution (media, community, audience), (4) proprietary datasets, (5) **domain-specific harnesses — "the agent that runs one industry's work"**, (6) robotics and physical AI, (7) physical products with a fan following, (8) compute and energy, (9) health, longevity and care, (10) marketplaces and social networks (for people **and agents**), (11) real assets, (12) **vertical agents**, (13) security.

## Counter-positions in the replies

- **@lgrig (platform-absorption objection)**: *"They'll use the agents you create to learn all your flows and tool calling then offer those services directly. The whole thing is basically a training exercise to replace every piece where a human might be involved."* — the strongest argument against the "rent the platform, own the domain" wedge, and unanswered.
- **@trypitchdotco**: *"Item 5 and item 12 are the exact same pitch deck with different valuation multiples."* — fair; Isenberg does not distinguish domain-specific harness from vertical agent.
- **@YGaitsgory**: *"The moat is knowing which work should stop existing."*
- **@RimasXYZ** asks the unanswered operating question: *"how do you tell if a workflow is worth owning?"*
